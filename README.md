# Avand — gold wallet and trading demo

وب آزمایشی فارسی برای خرید و فروش طلا. تمام قیمت‌ها، پرداخت‌ها و تسویه‌ها ساختگی‌اند.

## اجرا

Docker Desktop را اجرا کنید، سپس:

```sh
docker compose up --build -d
```

وب: http://localhost:3000 — RabbitMQ management: http://localhost:15678 (local demo credentials: `avand` / `avand_local`). سرویس‌ها فقط روی loopback میزبان منتشر می‌شوند. دیتابیس volume پایدار دارد؛ restart موجودی را پاک نمی‌کند.

برای توسعه با Node.js 22:

```sh
npm ci
docker compose up -d db rabbit
npm run migrate
npm start
# در ترمینال دیگر:
npm run worker
```

برای اجرای host از `HOST=127.0.0.1 npm start` استفاده کنید اگر فقط دسترسی محلی می‌خواهید. Docker API داخل container روی 0.0.0.0 است ولی port میزبان روی 127.0.0.1 bind شده است.

## تست

تست‌ها روی دیتابیس جداگانه اجرا می‌شوند و دادهٔ دمو را پاک نمی‌کنند. تنها بار اول:

```sh
docker compose exec db createdb -U avand avand_test
```

سپس:

```sh
npm run typecheck
npm test
```

`TEST_DATABASE_URL` اختیاری است و باید به دیتابیس با نام `avand_test` اشاره کند. هفت سناریوی مالی از PostgreSQL واقعی استفاده می‌کنند؛ تست worker نیز RabbitMQ واقعی می‌خواهد. تست worker صف جدا دارد.

## نمایش دمو

۱. در فرم «شارژ کیف پول»، مبلغ را ثبت و سپس در پنل درگاه «پرداخت موفق» بزنید. شارژ بدون کارمزد و بدون خرید طلا انجام می‌شود.
۲. «دریافت قیمت تازه» را بزنید؛ قیمت ماک هر ۳۰ ثانیه تغییر می‌کند و quote برای ۶۰ ثانیه ثابت می‌ماند.
۳. در خرید، «موجودی کیف پول» انتخاب پیش‌فرض است. با ثبت خرید، ریال و طلا اتمیک جابه‌جا می‌شوند و پرداخت تازه‌ای لازم نیست.
۴. برای سناریوهای callback خرید، «درگاه ماک (خرید مستقیم)» را انتخاب کنید. مسیر قدیمی API نیز سازگار مانده است.
۵. «موفق بدون callback» با inquiry worker پیدا می‌شود. پرداخت دیررس خرید، پس از انقضای quote، به کیف پول ریالی می‌رود.
۶. برای سناریوی واقعی verify ناموفق، درخواست شارژ یا خرید مستقیم بسازید و «کسر وجه، verify ناموفق» را بزنید. در جزئیات، paid/rejected و پیام رفع مغایرت دیده می‌شود؛ موجودی افزایش نمی‌یابد. اجرای تطبیق، gateway_only گزارش می‌کند. «تأیید مجدد درگاه ماک» نتیجه را اصلاح می‌کند و worker همان پرداخت را یک بار نهایی می‌کند؛ سپس گزارش تطبیق تازه بدون آن مغایرت خواهد بود. این عملیات بازپرداخت بانکی نیست.
۷. برای فروش قیمت تازه بگیرید. برداشت از ریال قابل استفاده است؛ شبا checksum معتبر می‌خواهد و پیش‌فرض نمونهٔ آزمایشی است.
۸. از تاریخچه، events، entries، jobs و اطلاعات charge/verify را ببینید. قطعی providerها از پنل پشتیبانی قابل کنترل است؛ موجودی و تاریخچه در قطعی قیمت هم نمایش داده می‌شوند.

برای سناریوهای ۱۰۰ درخواست و فروش هم‌زمان از تست خودکار استفاده کنید. UI تک‌کاربره است و نمایش دستی این موارد جایگزین تست نیست.

## API خلاصه

- `POST /api/quotes` → قیمت هر گرم ریال، زمان انقضا
- `POST /api/orders` با `Idempotency-Key`؛ شارژ مستقل: `{kind:"topup",amount:"100000000"}`
- خرید از کیف پول: `{kind:"buy",amount:"10000000",quoteId:"...",fundingSource:"wallet"}`
- خرید مستقیم درگاه: همان خرید با `fundingSource:"gateway"`؛ حذف این فیلد برای سازگاری به معنی gateway است
- فروش: `{kind:"sell",gold:"10000",quoteId:"..."}`؛ gold به میکروگرم
- برداشت: `{kind:"withdraw",amount:"100000",sheba:"IR..."}`
- `POST /api/mock/payments/:id` با `{mode:"success"}`؛ modes: success/failure/duplicate/late/missing/failed_verify
- `POST /api/mock/payments/:id/resolve-verification` تأیید مجدد پرداخت شارژشده با verify ناموفق؛ فقط ماک، پردازش مالی async
- `POST /api/gateway/callback/:id` فقط اعلان است؛ مبلغ/نتیجه از verify خوانده می‌شود
- `GET /api/balances`، `GET /api/orders`، `GET /api/orders/:id`
- `POST /api/support/reconcile`، `GET /api/support`
- `POST /api/support/jobs/:id/retry` برای dead job

اعداد مالی در API رشتهٔ صحیح هستند. amount ریال است، نه تومان. کارمزد معامله ۱٪، شارژ بدون کارمزد و مبنای قیمت ۱۰۰ میلیون ریال/گرم با نوسان هر ۳۰ ثانیه، صرفاً فرض دمو است. سیاست انقضا بر اساس زمان پرداخت در ماک است، نه زمان callback.

## بررسی انجام‌شده در این مرحله

- TypeScript typecheck و ۲۸ تست خودکار موفق؛ شامل ۱۰۰ درخواست هم‌زمان، رقابت خرید از کیف پول و برداشت، شارژ مستقل، feed سی‌ثانیه‌ای، verify ردشده پس از کسر وجه، replay پیام RabbitMQ، DLQ و بازیابی.
- اجرای واقعی همهٔ سرویس‌ها با `docker compose up --build -d` موفق.
- smoke از HTTP: شارژ با callback تکراری → خرید از کیف پول → کسر وجه و verify ردشده → رفع مغایرت → فروش → برداشت → تطبیق بدون مغایرت؛ جمع ledger برای هر دو دارایی صفر.
- بررسی syntax فایل JS و تست مرورگری مسیر شارژ → کسر وجه با verify ناموفق → رفع مغایرت → خرید از کیف پول موفق؛ موجودی و پیام‌های وضعیت در رابط تأیید شدند. ویدیوی تحویل هنوز ضبط نشده.

برای تکرار smoke با ایجاد سفارش‌های ساختگی تازه و بدون پاک‌کردن داده‌ها:

```sh
node scripts/smoke.mjs
```

ارتقا از نسخهٔ قبلی با همان `docker compose up --build -d` انجام می‌شود؛ migration افزایشی است، حساب‌ها و سندهای قبلی حذف نمی‌شوند. درخواست‌های idempotent قدیمی همچنان پاسخ ذخیره‌شدهٔ خود را دریافت می‌کنند. حالت‌های آزمایشی failed_verify که در نسخهٔ قبلی ایجاد شده‌اند بازنویسی نمی‌شوند؛ برای رفتار جدید سفارش تازه بسازید.
